# Phase 1 검수 워크시트 — P2 슈즈 8건 styles

작성일: 2026-07-30

상태: 초안(미확정) — 사람 검수 대기

관련 문서: [conversational-discovery.md](conversational-discovery.md) 4-2·5-1-1·11절(Phase 1 진행 상태)

## 0. 이 문서의 목적과 범위

`conversational-discovery.md` 11절 Phase 1 진행 상태표의 **P2(슈즈 8건 styles, 8건)** 항목을
사람이 확정할 수 있는 형태로 만든 워크시트다. 저장소 전체를 검색했으나 이 8건을 다루는
기존 워크시트 파일은 없었다(`docs/backend/native/conversational-discovery.md` 자체에
"검수 워크시트는 산출돼 있다"는 서술만 있고, 실제 워크시트 파일·표는 어디에도 없었다).
그래서 이 문서를 신규로 작성한다.

이 문서는 코드를 수정하지 않는다. `backend/resources/store_search_facets/` 아래 실제
오버레이 파일에도 쓰지 않는다 — 확정은 사람 몫이다(3절 JSON은 검수 후 사람이 그대로
복사해 넣을 수 있도록 준비한 초안일 뿐이다).

## 1. 확인한 현재 상태

- `backend/resources/store_search_facets/_vocabulary.json` — `styles` 허용값은
  `["스포츠", "캐주얼", "컨템포러리", "명품", "골프"]` 5개뿐이다. 이 문서의 제안도 이
  값만 사용한다.
- `backend/resources/store_search_facets/fashion.json` — 현재 `{"version": 1, "stores": {}}`로
  **비어 있다.** 즉 패션 오버레이는 아직 한 건도 반영되지 않은 상태다.
- `backend/app/repositories/store_facets.py`의 `_SUBCATEGORY_TO_STYLES`는 슈즈를 다루지
  않는다(주석: "슈즈·잡화·시계·아이웨어·이너웨어 등은 스타일이 아니라 무엇을 파는지를
  말하는 품목 축이라 여기서 다루지 않는다"). 즉 슈즈 8건은 파생으로 절대 채워지지 않고
  오버레이로만 채울 수 있다 — 이 문서가 존재해야 하는 이유와 일치한다.
- `backend/tmp/probe/facet_sample.json`·`facet_counts.json`은 이전 조사에서 남긴 프로브
  결과로 보이며(전체 1640건이 `null_or_str_null`), 슈즈 8건 전용 워크시트는 아니다.

## 3. 오버레이 JSON 반영안 (검수 후 사람이 그대로 복사해 사용)

`conversational-discovery.md` 5-1-1절 스키마(축 단위 오버레이, `name`은 참고용 중복 정보,
같은 `store_id`가 다른 오버레이 파일과 중복되면 안 됨)에 맞춘 초안이다. 아래 JSON은
**제안값 그대로이며 사람 검수 전 확정값이 아니다.** 확정 시 아래 값을 그대로 두거나
검수 결과로 교체해 실제 오버레이 파일에 반영하면 된다.

현재 `backend/resources/store_search_facets/fashion.json`이 이미 있고 `{"stores": {}}`로
비어 있으므로, 이 8건을 `fashion.json`에 채울지 별도 `shoes.json` 파일로 분리할지는
검수자가 정할 사항으로 남긴다(4절 "사람이 확정해야 할 것" 참고). 아래 블록은 파일
선택과 무관하게 `stores` 안에 넣을 내용이다.

## 4. 사람이 확정해야 할 것

1. **8건 각각의 styles 값 자체.** 이 문서의 제안은 브랜드 일반 상식에 근거한 추정이며,
   실제 더현대서울 매장 자료(공식 브랜드 소개, 입점관 정보)로 검증되지 않았다.
2. **골든구스(명품 vs 캐주얼)·캠퍼투게더 스토어(캐주얼 vs 컨템포러리)의 병기 여부.**
   한 값만 남길지 두 값 다 넣을지.
3. **오버레이 파일 위치.** 8건을 기존 `fashion.json`(현재 비어 있음)에 채울지, 슈즈
   전용 `shoes.json`으로 분리할지. `store_facets.py`는 카테고리별로 파일을 쪼갤 수
   있다고 명시하므로 스키마상 어느 쪽도 가능하다.
4. **검수 완료 후 시드 검증 통과 여부.** `resolve_facets`/`validate_overlay`(
   `backend/app/repositories/store_facets.py`)로 vocabulary·중복·존재 여부를 실제로
   검증해야 한다(이 작업에서는 실행하지 않았다 — 오버레이 파일에 아무것도 쓰지 않았으므로
   대상이 없다).
5. **P1(레스토랑 cuisine 49건)·P3(패션 신발 취급 여부 196건)·P4(분류 오류 의심 9건)는
   이 문서의 범위가 아니다.** 11절 진행 상태표의 별도 항목으로 남아 있다.
