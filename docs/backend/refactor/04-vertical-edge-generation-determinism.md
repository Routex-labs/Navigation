# 04. 수직 이동 간선 생성 알고리즘 결정성 확보

브랜치(제안): `fix/vertical-edge-generation-determinism`

## 배경

위치 기반 에스컬레이터 매칭이 가장 가까운 미사용 노드를 순차 선택하는 방식이면, 후보가 비슷할 때 입력 순서에
따라 결과가 달라질 수 있다. 엘리베이터 샤프트 그룹핑도 첫 대표 좌표 기준 탐욕적 구성이면 같은 샤프트가
여러 그룹으로 쪼개지거나, 가까운 다른 샤프트와 잘못 병합되거나, 한 샤프트의 모든 층 쌍을 연결해 간선 수가
`O(F²)`로 증가하는 문제가 있다.

## 범위(백엔드만)

Studio 시드 어댑터의 수직 전이 생성 로직(`backend/scripts/seed/studio_adapter.py` 등).

## 작업 항목

1. 입력을 층 level과 node ID 기준으로 안정 정렬(stable sort)한 뒤 매칭을 수행한다.
2. 근접 매칭에 bipartite minimum-cost matching을 적용해 순차 탐욕 선택을 대체한다.
3. 엘리베이터 샤프트 그룹핑에 DBSCAN 또는 union-find 기반 군집화를 적용한다.
4. 이름·위치·원본 topology가 충돌하면 자동으로 하나를 선택해 연결하지 않고, 검증 오류 또는 사람이 확인할
   override 대상으로 분리한다(03번에서 만든 validator의 unresolved 항목으로 보고).
5. 동일 입력의 permutation(순서만 바꾼 입력)에서 결과가 동일한지 확인하는 property test를 추가한다.
6. 엘리베이터 간선 수를 줄이기 위해 "각 층 엘리베이터 노드 ↔ 엘리베이터 샤프트 hub" 가상 hub node 도입을 검토한다 — 샤프트당 간선을 `O(F²)`에서 `O(F)`로 줄인다.

## 완료 기준

- [x] 입력 순서를 바꿔도 생성 결과(간선 집합)가 동일하다. — 층 순서·노드 순서를 섞은 permutation property test(`tests/unit/test_vertical_transfers_determinism.py`)로 확인.
- [ ] 샤프트별 간선 수가 층 수에 선형으로 증가한다(`O(F)`). — **이번 브랜치에서 제외(결정성 우선).** 아래 "남은 작업" 참고.
- [x] 동일 샤프트/인접 샤프트 분류에 대한 테스트가 통과한다. — 나란한 엘리베이터 뱅크가 열별로 분리됨을 확인(`test_인접한_엘리베이터_뱅크는_열별로_분리된다`).
- [x] 원본 topology와 충돌하는 위치 기반 폴백이 자동으로 적용되지 않는다. — 최적 매칭이 애매한 짝을 임의 선택하지 않고, 짝을 못 얻은 노드는 `unresolved`로 보고한다.

## 설계 결정

- **매칭: 순차 탐욕 → 결정적 최소비용 매칭(`scripts/transform/vertical_matching.py`).** scipy 없이 표준
  헝가리안을 직접 담아, a·b를 id로 정렬한 고정 행렬에서 최적 할당을 구한다. 입력 순서가 어떻든
  같은 짝이 나온다(동점 최적해도 행렬이 고정이라 하나로 결정).
- **엘리베이터 군집화: union-find 대신 층별 최소비용 추적.** 원문서는 union-find/DBSCAN을
  제안했으나, 나란히 붙은 엘리베이터 뱅크는 서로 반경(`MATCH_RADIUS_M`) 안이라 순수 union-find로
  합치면 한 덩어리가 되어 한 층에 여러 노드가 들어가고, 그러면 샤프트를 특정할 수 없어 전부
  버려진다(실데이터 파손). 대신 층을 level 순서로 훑으며 각 층 노드를 기존 샤프트에 최소비용
  매칭으로 잇는다 — 뱅크의 각 열이 자기 샤프트로 분리되고, 층 순서·매칭이 모두 결정적이라
  입력 순서와 무관하다.

## 남은 작업(별도 브랜치)

- **엘리베이터 간선 `O(F²)` → `O(F)` 축소(원 item 6).** 지금은 샤프트가 서비스하는 모든 층쌍을
  직행으로 잇는다(`O(F²)`). 가상 hub로 `O(F)`로 줄이려면 **라우팅 비용 모델을 바꿔야 하고**(고정
  탑승비를 각 직행 쌍이 한 번만 물게 하는 현재 모델은 hop 비례 비용 `|rank_i−rank_j|`가 단일 hub로
  분리되지 않는다) 가상 노드가 생겨 **클라이언트 계약**에도 영향이 간다. 사용자에게 보이는 경로
  선택이 달라질 수 있는 변경이라 결정성 작업과 분리했다.
